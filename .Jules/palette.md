## 2024-09-13 - [Semantic HTML for Login Success Redirect]
**Learning:** In the login success redirect page (`codex-rs/login/src/assets/success.html`), the redirect "button" was implemented as a non-interactive `<div>` element instead of a semantic `<a>` link. This is a common accessibility issue where developers style a `<div>` to look like a button or link but miss the built-in keyboard navigation (focusing via Tab and activation via Enter) provided by semantic tags. Furthermore, an explicit `aria-label` was missing for screen readers, and `focus-visible` styling was absent, making keyboard navigation less obvious.
**Action:** Replaced the non-interactive `<div>` with a semantic `<a>` tag with an `href` set dynamically by JS, added an `aria-label` for screen reader users ("Redirecting to setup"), and ensured explicit `focus-visible` CSS rules for visual keyboard interaction. When converting non-semantic elements into semantic ones, always verify and explicitly define default visual overrides like `text-decoration: none` to prevent unintended browser default visual regressions.
