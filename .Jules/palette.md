## 2024-03-24 - Screen Reader Announcement on Redirects
**Learning:** When creating a dynamic redirect countdown or changing state via display toggling, placing `aria-live` directly on the elements transitioning from hidden to visible is unreliable. A dedicated, permanently present, visually hidden DOM element using inline styles (to avoid custom CSS classes) must be used to reliably announce dynamic changes or initialization states. For short countdowns, do not update an `aria-live="assertive"` region every second, as this causes the screen reader to constantly interrupt itself (spamming). Instead, announce the initial intent once, or use `aria-live="polite"`. Also, do not use `setTimeout` to delay the first tick of a countdown if it controls the UI, as it freezes the UI initially; instead, ensure the visual state updates immediately by calling the tick logic upfront before the timeout loop.
**Action:** Always include a permanently present, visually hidden `aria-live` container at the body level for dynamic announcements, announce short countdowns only once or with `polite` to avoid spamming, and ensure UI logic calls immediately before any timeout delays to prevent visual freezing.
